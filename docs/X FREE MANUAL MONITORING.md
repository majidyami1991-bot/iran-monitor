# X-FREE — Manual Monitoring of X Accounts

The 36 X accounts in the client's source list are monitored **by hand**:
an analyst registers the URL of a specific post they have read. Nothing in
the system talks to X. There is no official X API (paid or free), no
scraping, no headless browser, no cookie or session, no Nitter or RSS
bridge, and no scheduler.

## Accounts

`config/sources/x-free-readiness.json` (v1.0.0) is generated by
`scripts/build_x_free_readiness.py` from `source-registry.json` and
`source-occurrences.csv`. There are 38 raw occurrences and 36 unique accounts.
Two handles are duplicates: `@ThetiMapping` and `@manniefabian` (each has 2
provenance rows). Every account has `enabled=false`, `collection_mode=manual`,
`official_api_enabled=false`, and keeps its source_id and sites.docx
provenance. On startup the API inserts these accounts into `x_accounts`; it
never overwrites a row that already exists.

## Registering a post

`POST /api/v1/social/manual-posts` only works when
`SOCIAL_MANUAL_INGEST_ENABLED=true`. It is enabled on the preview through
`PREVIEW_SOCIAL_MANUAL_INGEST_ENABLED`. Production has no such setting, so it
stays off.

**URL rules:**
- HTTPS only.
- The host must be exactly x.com or twitter.com (with or without `www.` or
  `mobile.`). Look-alike domains and t.co are rejected.
- The path must be `/{handle}/status/{id}`.
- The handle must be one of the 36 accounts.
- The URL is canonicalised to `https://x.com/{handle}/status/{id}`;
  duplicates return 409.

**Text:** optional. If present, it is recorded as `text_source=analyst_entered`,
`text_is_x_api_output=false`. If absent, `link_only`: no text is invented.

**Security:**
- Same-origin CSRF token (HMAC, 2 h), checked together with the browser's
  Origin header, which the web proxy sets.
- JSON-only writes, so a cross-site HTML form post gets a 415.
- Request models reject unknown fields.
- Text is stored verbatim and rendered as React text; `dangerouslySetInnerHTML`
  is never used.
- Content-Security-Policy on every page.

The form has a "preview before saving" step (`dry_run`), which writes nothing.

## Official embed

This is optional and loads **only on click**, after a notice that the browser
will contact platform.twitter.com. It uses X's `widgets.createTweet` for that
one post id (`dnt: true`). The embed is not a data source. It has four states
(loading, loaded, unavailable, blocked), each with a fallback card and a
"view on X" link.

## Optional analysis (analyst-triggered only)

`POST /api/v1/social/posts/{id}/ai` runs on analyst-entered text only, and
every run is recorded in the history. Available actions:

| Action | Engine | Label |
|---|---|---|
| translate / summarize | AI gateway (free-only guard) | «تولیدشده با هوش مصنوعی · بازبینی انسانی نشده» |
| classify | taxonomy v3 rules | suggestion; the analyst's topic is not changed |
| entities | rule-based name extraction | suggestion |
| suggest_event | events sharing ≥2 names | suggestion |

If the provider is unavailable, the post is unchanged and the status is
reported.
